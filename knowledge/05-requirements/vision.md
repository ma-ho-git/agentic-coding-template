# Projektvision

<!-- template-placeholder -->
> **Für ein eigenes Projekt:** diese Datei vollständig ersetzen. Was hier steht, ist die
> Vision **dieses Templates** — sie dient zugleich als ausgefülltes Beispiel dafür, wie die
> Datei aussehen soll.

## Kurz

Das Warum des Projekts, auf einer Seite. Wer sie gelesen hat, versteht, wofür das System
existiert und woran sein Erfolg gemessen wird — ohne eine einzige Anforderung zu kennen.

## Problem

Vibe-Coding mit Agenten produziert schnell Ergebnisse und ebenso schnell Wildwuchs. Ohne
Struktur passiert typischerweise Folgendes:

- Es wird sofort codiert, ohne dass jemand festgehalten hat, *was* eigentlich entstehen soll.
- Wissen bleibt im Sitzungsverlauf und ist beim nächsten Start verloren.
- Dasselbe Problem wird zweimal gelöst, weil die erste Lösung nirgends steht.
- Regeln stehen in Prosa, werden aber nicht durchgesetzt — also gelten sie nur, solange sie
  jemandem gerade präsent sind.
- Mehrere Agenten arbeiten aneinander vorbei, weil es keinen gemeinsamen Aufgabenstand gibt.

## Zielartefakt

Eine klonbare Projektvorlage, die Claude Code und Claude Cowork ein Gerüst gibt: verbindliche
Regeln, eine Obsidian-kompatible Wissensdatenbank mit Aufgabenverwaltung, verpflichtende
Anforderungserhebung vor dem Codieren — und Prüfungen, die all das durchsetzen statt es zu
empfehlen.

## Erfolgskriterien

- Nach `git clone` und `/bootstrap` kann ein Agent ohne weitere Einrichtung anfangen.
- Eine Regelverletzung wird von einer Prüfung abgelehnt, nicht bloß angemahnt.
- Nach einem Sitzungsende ist der Projektstand aus dem Repository lesbar, nicht aus dem
  Gesprächsverlauf.
- Zu jeder Aufgabe ist erkennbar, welche Anforderung sie erfüllt.
- Das Template hält seine eigenen Vorgaben ein — nachweislich, nicht behauptet.

## Nicht-Ziele

- **Keine vollständige Umsetzung von Sommervilles Software Engineering.** Was übernommen wird
  und was nicht, steht in [[Sommerville Software Engineering - was das Template übernimmt]].
- Kein Ersatz für menschliche Entscheidungen: Umfang, Prioritäten, Freigaben und das Öffnen
  des Startgates bleiben beim Nutzer.
- Keine Werkzeugkette für große Teams — Zuschnitt ist ein Mensch mit ein bis zwei Agenten.
- Keine Sprach- oder Framework-Vorgabe über das Stack-Profil hinaus.
